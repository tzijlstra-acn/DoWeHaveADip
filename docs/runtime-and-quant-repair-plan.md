## 4. Confirmed defects (prioritised)

### P0 — Incorrect chart output (wrong data to drawdown_chart)

**Location:** `today.py:217`, `compare.py:444`, `compare.py:577`

The raw benchmark price series is passed to `drawdown_chart()` instead of a pre-computed drawdown series. The chart's y-axis shows `price * 100` instead of `(price/peak - 1) * 100`. This means the "Drawdown history" chart is meaningless — it shows a scaled price chart, not a drawdown waterfall.

**Fix:** Call `drawdown_chart(drawdown(signal_series), ...)` — or have `drawdown_chart` validate that all input values are ≤ 0.

### P1 — `drawdown_chart` has no input validation

**Location:** `ui/charts.py:drawdown_chart`

The function accepts any `pd.Series` without checking whether values are ≤ 0 (drawdown) or positive (raw prices). This makes it trivially easy to pass wrong data silently.

**Fix:** Add `if series.max() > 0: raise ValueError(...)` guard.

### P2 — "Calendar days from high" shows trading-row count

**Location:** `today.py:122–127`, `compare.py:269–274`

The row-counting loop:
```python
for i in range(len(at_peak) - 1, -1, -1):
    if at_peak.iloc[i]:
        break
    days_since_high += 1
```
counts rows, not calendar days. On a daily index, 50 trading rows ≈ 70 calendar days. The label says "Calendar days" but the number is trading rows.

**Fix:** Find the most recent ATH date and compute `(last_date - ath_date).days`.

### P3 — Episode study failures silently dropped

**Location:** `src/dipdca/quant/ath_episodes.py:392`

```python
except (ValueError, KeyError):
    continue
```

When `run_ath_deployment` raises inside `study_episode`, the exception is caught and the loop continues. The returned `EpisodeStudy` is missing ATH policy outcomes but is not None, so callers have no way to detect incomplete results.

**Fix:** Either propagate the exception or record a marked error state in the return value.

### P4 — `fmt_pct` default precision is 1 decimal (insufficient)

**Location:** `ui/formatting.py:fmt_pct`

`fmt_pct(0.041)` returns `"4.1%"`. Financial tables need `"4.10%"`. The default `decimals=1` is insufficient for drawdown/return display.

**Fix:** Change default `decimals=1` to `decimals=2`.

### P5 — `today.py` silently drops ATH episode summary errors

**Location:** `today.py:249`

```python
except Exception:
    _crossed = []
    _recovered = []
```

Any exception (including logic bugs in `find_ath_episodes`) causes the historical context section to display "No historical ATH episode crossed X%" rather than surfacing the error. Bugs in the episode engine become invisible.

**Fix:** Log the exception and show `st.exception(exc)` or at minimum `st.warning(...)` with the error text.

### P6 — `advanced_exit.py` NAV return displayed as fraction (format bug)

**Location:** `app_pages/advanced_exit.py:390`

`format="%.2f%%"` applied to a raw fraction value (e.g., `0.50`) displays `"0.50%"` instead of `"50.00%"`. The investment return is 50× too small in the display.

**Fix:** Pre-multiply `investment_return * 100` before placing it in the DataFrame, or use `format="%.2f"` with a column unit label.

### P7 — `advanced_fx.py` uses `fillna(1.0)` (silent 1:1 parity)

**Location:** `app_pages/advanced_fx.py:151`

When ECB FX data is missing for leading dates, `fillna(1.0)` silently applies 1:1 parity instead of raising or warning. This is scoped to the FX decomposition page only — the main backtest uses `instrument_to_base_currency` which correctly raises `ValueError`.
